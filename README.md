# Погодження внутрішніх документів

Курсова робота з кросплатформеного програмування, варіант 25. У JavaFX можна вести авторів, документи та рецензентів, подавати запити на погодження й розраховувати їхній пріоритет.

## Що потрібно для запуску

JDK 21, Maven 3.9, MySQL та Apache Tomcat 9.x. Перевірте версію JDK командою `mvn -version`. Наведені нижче команди PowerShell виконуються з каталогу, де лежать `database.sql`, `client/` і `server/`.

| Шлях | Призначення |
|---|---|
| `server/` | Maven WAR. Servlet API 4.0.1 (`javax.servlet`), Jackson, Service, DAO, JDBC та MySQL Connector/J |
| `server/src/test/java/` | Модульні тести JUnit 5, які запускаються окремо від сервера, MySQL та JavaFX |
| `client/` | JavaFX 21, HTTP-клієнт та імпорт документів |
| `client/sample-data/documents.csv` | Два приклади документів для імпорту |
| `diagrams/` | Схеми бази даних, архітектури й переходів між станами |

## Підготовка MySQL

Для першого запуску імпортуйте `database.sql` у phpMyAdmin або виконайте його через команду `source database.sql` у консолі MySQL з каталогу проєкту. **Скрипт видаляє та заново створює навчальну базу `kpp25_approval_demo`.** Якщо потрібно зберегти наявні записи, використовуйте вже підготовлену базу. Після початкового заповнення таблиці містять двох авторів, двох рецензентів, два документи та три запити.

## Запуск сервера

У PowerShell задайте каталог Tomcat та ім’я користувача БД. За потреби перед запуском задайте `DB_PASSWORD` та `DB_URL` у середовищі процесу Tomcat. Стандартна адреса — `jdbc:mysql://localhost:3306/kpp25_approval_demo`.

```powershell
$tomcat = 'C:\tools\apache-tomcat-9'
$env:DB_USER = 'root'
mvn -f server/pom.xml clean test
mvn -f server/pom.xml clean package
Copy-Item server/target/approval-server.war "$tomcat/webapps/"
& "$tomcat/bin/catalina.bat" run
```

Залиште Tomcat відкритим. У другому вікні перевірте `Invoke-RestMethod http://localhost:8080/approval-server/authors`. Має повернутися список авторів у форматі JSON.

## Запуск клієнта

```powershell
cd client
mvn clean javafx:run
```

Для іншої адреси сервера задайте `APPROVAL_API_URL` перед запуском клієнта. На вкладках можна додавати записи, вибирати рядок для редагування або видалення й оновлювати таблицю. Зміни проходять через HTTP, Servlet, Service та DAO до MySQL.

## Імпорт документів

На вкладці «Документи» залиште шлях `sample-data/documents.csv` або введіть шлях до свого файла. Кодування UTF-8, роздільник — крапка з комою. Формат цього проєкту передбачає один документ на рядок, без роздільника чи переносу рядка всередині поля.

```text
registration_number;title;author_id;criticality_score;dependent_process_count
ВН-003;Порядок обліку обладнання;1;65;2
```

Усі п’ять полів обов’язкові. Номер документа унікальний, автор має існувати. Критичність — ціле число від 0 до 100, кількість залежних процесів — ціле невід’ємне число. Кнопка «Імпорт CSV» запускає JavaFX Task. Індикатор відображає частку опрацьованих непорожніх рядків. Неприпустимі рядки пропускаються, причини потрапляють до консолі клієнта. Після завершення таблиця оновлюється. Якщо зв’язок обірвався, перевірте таблицю перед повторенням: сервер міг зберегти останній документ до втрати відповіді.

## Контрольний приклад

У початковій базі для запиту №1 виберіть дату оцінки 18.11.2026. До строку два дні, критичність документа 80, залежних процесів три. Сервер обчислить **0,40 × 80 + 0,35 × 80 + 0,25 × 60 = 75**. Новий запит проходить послідовно стани «Чернетка», «Подано», «Розгляд», «Схвалено». Спробу пропустити стан сервер відхиляє.

Для перевірки помилок введіть у полі шляху `sample-data/documents-check.csv`. Рядки 2–4 містять відповідно неправильну кількість полів, текст замість числа й посилання на відсутнього автора. Якщо номер `DEMO4` вільний, останній рядок збережеться. Очікуваний підсумок — додано 1, пропущено 3.
